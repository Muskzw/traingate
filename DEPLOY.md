# Deploying the TrainGate demo to Render (free)

Goal: a public URL a client can open, click through a real gated course, and
see a verifiable certificate — without you paying for anything yet.

## What the free tier does and doesn't do

| | |
|---|---|
| Cost | $0, no credit card |
| Disk | **Ephemeral.** The database and uploaded decks are wiped on every deploy and on restart after idle. |
| Idle | Sleeps after 15 minutes. First request after that takes ~50 seconds to wake. |
| Demo data | Rebuilt automatically on every boot (`SEED_DEMO=true`), so a wipe self-heals. |

The reset is fine for a demo and bad for real use. When a client signs up for
real, move to a paid instance with a persistent disk, or Fly.io with a volume.

## Steps

### 1. Put the code on GitHub

Create an empty **private** repo called `traingate` at
https://github.com/new (no README, no .gitignore), then:

```bash
git init
git add -A
git commit -m "TrainGate"
git branch -M main
git remote add origin https://github.com/<your-username>/traingate.git
git push -u origin main
```

`data/`, `.env` and `node_modules/` are already gitignored, so no database or
secrets go up.

### 2. Create the service

1. Go to https://dashboard.render.com → **New** → **Blueprint**.
2. Connect your GitHub account and pick the `traingate` repo.
3. Render reads `render.yaml` and creates a free web service. Click **Apply**.

First build takes 2–4 minutes (`better-sqlite3` compiles or pulls a prebuild).

### 3. Set `PUBLIC_URL`

Once Render gives you the URL (something like
`https://traingate-xxxx.onrender.com`), go to the service → **Environment** and
set `PUBLIC_URL` to it. This is what gets printed on certificates as the
verification link. Save; the service redeploys.

### 4. Check it

- `https://your-url.onrender.com/` — landing page
- Click **Take a tour with demo data** — signs in as a demo learner
- `https://your-url.onrender.com/api/health` — should show `"demo": true`

Demo accounts (recreated on every boot):

| Account | Email | Password |
|---|---|---|
| Administrator | `admin@demo.test` | `demo1234` |
| Learner | `learner@demo.test` | `demo1234` |

## Turning on course generation later

Course generation is the only feature that needs the Anthropic API. Until a key
is set, the Courses page shows a notice and the upload button is disabled —
everything else works.

When a client funds a key:

1. Buy credits at https://console.anthropic.com → **Plans & Billing**.
2. Create a key under **API Keys**.
3. Render → your service → **Environment** → set `ANTHROPIC_API_KEY`.
4. Save. The service restarts and the upload button goes live.

`render.yaml` defaults to `claude-sonnet-5` at `medium` effort to keep the cost
per course low. Raise to `claude-opus-5` / `high` if the output needs it.

## What to fix before this is a real product

- **Persistent storage.** Free tier data loss makes real signups impossible.
- **`PLATFORM_ADMIN_PASSWORD`** is generated by Render — read it from the
  dashboard, don't leave it lying around.
- **Cold starts.** A 50-second first load looks broken to a client. Open the URL
  yourself a minute before any demo call.
